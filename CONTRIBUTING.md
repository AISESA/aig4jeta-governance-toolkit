# Contributing to AIG4JETA Governance Toolkit

Thank you for your interest in contributing to the AISESA AI Working Group's governance toolkit!

This guide explains how to contribute effectively and ensures our collaborative work maintains high quality and coherence.

---

## Who Can Contribute?

- **AISESA Working Group Members**: Full access to contribute to all materials
- **AISESA Members**: Welcome to contribute use cases, feedback, and suggestions
- **Broader Community**: We appreciate external perspectives and expertise

**Note**: Major governance artifact changes (TRUST Matrix, Ethics Principles) require working group review and approval.

---

## Ways to Contribute

### 1. Share a Use Case
Real-world examples strengthen our frameworks. If you're using AI in energy systems, please share your experience.

**Process**:
1. Use the [Use Case Template](use-cases/TEMPLATE-use-case-description.md)
2. Fill in as much detail as comfortable (can be anonymized)
3. Submit via pull request or email to working group chair
4. We'll review, provide feedback, and integrate

### 2. Provide Feedback on Governance Artifacts
Help refine the TRUST Matrix, Ethics Principles, and other frameworks.

**Process**:
1. Open an [Issue](../../issues) using the "Governance Artifact Change" template
2. Clearly describe the proposed change and rationale
3. Working group will discuss and respond
4. If accepted, submit a pull request with the changes

### 3. Contribute to Surveys or Research
Help design better research instruments and methodologies.

**Process**:
1. Review survey drafts in `/surveys`
2. Suggest additional questions, refinements, or methodological improvements
3. Comment directly via pull request or create an Issue

### 4. Improve Documentation
Make our materials more accessible and understandable.

**Process**:
1. Fix typos, broken links, or unclear explanations via pull request
2. For major documentation restructuring, open an Issue first to discuss
3. Focus on clarity, accessibility, and plain language

### 5. Participate in Discussions
Engage with ideas, questions, and debates.

**Process**:
1. Use [GitHub Discussions](../../discussions) for open-ended conversations
2. Use [Issues](../../issues) for specific, actionable items
3. Be respectful, constructive, and solution-oriented

---

## Contribution Process

### For Small Changes (typos, links, minor clarifications)
1. Fork the repository
2. Make your changes
3. Submit a pull request with clear description
4. Maintainer will review and merge quickly

### For Substantive Changes (new content, framework modifications)
1. **First**: Open an Issue to discuss the proposed change
2. **Then**: Wait for working group feedback/approval
3. **Finally**: Submit pull request implementing the agreed changes
4. PR will be reviewed and merged after approval

### For Governance Artifacts (TRUST Matrix, Ethics Principles)
These are **authoritative documents** requiring extra care:
1. Propose changes via Issue with detailed rationale
2. Working group discusses (may take 1-2 meeting cycles)
3. If approved, designated contributor drafts changes
4. Working group reviews draft
5. After approval, changes merged and version number incremented

## Branching & Versioning

### Branches
- `main`: Stable, published versions of all documents
- Feature branches: Use descriptive names like `update-trust-matrix-transparency` or `add-use-case-forecasting`

### Versioning
Governance artifacts use semantic versioning:
- `v0.1`, `v0.2`: Draft/development versions
- `v1.0`: First stable release
- `v1.1`, `v1.2`: Minor updates and clarifications
- `v2.0`: Major revisions or restructuring

All version changes are logged in each document's "Version History" section and in `/governance/version-history.md`.

## Style Guidelines

### Writing Style
- **Plain language**: Avoid jargon where possible; explain technical terms
- **Inclusive**: Use gender-neutral language; consider diverse audiences
- **Concise**: Be clear and direct; respect readers' time
- **Action-oriented**: Focus on practical application, not abstract theory

### Formatting
- Use Markdown formatting consistently
- Headers: `#` for title, `##` for main sections, `###` for subsections
- Lists: Use `-` for unordered lists, `1.` for ordered lists
- Emphasis: `**bold**` for key terms, `*italic*` for emphasis
- Code blocks: Use ` ``` ` for code or data examples
- Links: Use descriptive link text, not "click here"

### File Naming
- Lowercase with hyphens: `ai-ethics-principles-v0.1.md`
- Include version numbers for governance artifacts
- Use descriptive, searchable names

## Review Process

### Timeline
- **Minor changes**: 1-3 days
- **Substantive contributions**: 1-2 weeks
- **Governance artifact updates**: 2-4 weeks (requires working group meeting review)

### Who Reviews?
- Working group co-chairs for governance artifacts
- Assigned reviewers for use cases and documentation
- Community feedback welcome via comments

### Approval Criteria
- Aligns with working group mandate and values
- Maintains quality and coherence
- Properly documented and formatted
- No conflicts with existing commitments
